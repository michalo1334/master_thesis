\chapter{Theoretical Background}
\label{ch:theory}

This chapter defines the model used by the implementation. It is a static context graph plus a finite-horizon stochastic state-transition simulation. It is informed by attack-graph literature, but it is not a MulVAL, NetSPA, Bayesian attack graph, or multiple-prerequisite graph implementation.

\section{Context Graph}

Let $G = (V, E)$ be a typed graph containing network segments, hosts, services, vulnerabilities, credentials, and their relationships. A canonical reachability edge is a directed policy from one segment to another with protocol and port constraints. It is not a host-to-service attack edge.

When a trial needs connectivity, the system deterministically materializes an operational flow from a source host to a target service only when both hosts belong to the policy's segments and the service matches its protocol and port constraints. These flows are transient. They are not stored in the canonical graph or treated as user-authored topology.

\section{Attacker State and Transitions}

One trial begins with a configured initial foothold. Its state records the attacker's current footholds, privileges, and attempted actions. At transition $t$, the implementation derives the eligible action set $A_t$ from the graph and state. If $A_t$ is nonempty, it selects one action uniformly:

\[
P(a \mid A_t) = \frac{1}{|A_t|}, \qquad a \in A_t.
\]

The selected action is then evaluated. A remote exploit uses the vulnerability's separately assigned stylized success probability. Credential reuse succeeds when its modeled preconditions hold. Failed actions and the configured attempt cap determine which actions remain eligible. The process stops when no action is eligible or when the configured iteration limit is reached.

CVSS is not converted into an exploit-success probability. CVSS communicates vulnerability characteristics and severity; its Base score is intended to be supplemented with temporal and environmental information for a particular environment~\cite{cvss31}. The implementation uses CVSS only for its direct priority baseline.

\section{Measured Quantity}

For trial $r$, let $F_r$ be the final set of compromised host footholds, including the initial foothold. The modeled blast-radius count is

\[
B_r = |F_r|.
\]

For $R$ trials, the reported expected blast radius is the sample mean

\[
\widehat{\mathbb{E}}[B] = \frac{1}{R}\sum_{r=1}^{R} B_r.
\]

The host heatmap estimates $\hat{\beta}(h) = R^{-1}\sum_r \mathbb{1}[h \in F_r]$. These are outputs of the specified model, not measurements or forecasts of real attacker movement.

\section{Defensive Actions}

The system models vulnerability-exposure removal, segment-policy removal, and credential revocation. All current actions have unit cost, so a budget $k$ limits the number of actions rather than deployment cost, operational disruption, or rollback effort. A policy removal can affect many operational flows; it is therefore not economically comparable to patching one exposure.

Simulation-informed greedy selection keeps only candidates with a strictly positive estimated reduction in expected final compromised-host count. Simulated annealing evaluates and applies a jointly selected plan only when that plan improves on the baseline estimate. CVSS-priority and topology-based segmentation are direct ranking baselines, not estimates of expected risk reduction.

\section{Scope}

The model assumes a fixed synthetic topology, policy, vulnerability catalog, attacker rules, and finite horizon. It does not model real exploit likelihood, legitimate traffic, operational availability, asset value, recovery, attacker profiles, topology-density sensitivity, or cost-aware deployment. A future evaluation must preserve the complete scenario, configuration, random seed, selected action list, and per-trial outcomes, then use independent evaluation trials after strategy selection.
