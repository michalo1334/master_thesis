\section{Design Goals}
\label{ch:design:goals}

The system is designed to satisfy a small set of explicit goals. The goals are partitioned into functional and non-functional groups.

\begin{itemize}
	\item \textbf{Functional:}
	\begin{itemize}
		\item Construct an attack graph from a network topology and a CVE feed.
		\item Simulate attacker propagation by Monte Carlo sampling and produce a blast-radius map.
		\item Recommend defensive actions (segmentation edges, vulnerability patches) that minimize the resulting blast radius.
	\end{itemize}
	\item \textbf{Non-functional:}
	\begin{itemize}
		\item Reproducible results: a given topology and seed must produce the same blast-radius map across runs.
		\item Reasonable scale: the pipeline should run end-to-end on a 200-host topology in under one minute on a single workstation.
		\item Implementation fits in a small number of Elixir source files, to make the system easy to study and modify~\cite{ou05mulval}.
	\end{itemize}
\end{itemize}

\section{Data Layer}
\label{ch:design:data}

The data layer consists of two inputs. The first is a \emph{network topology} described as a list of host/service pairs plus the network reachability relation (which host can initiate connections to which other host, on which port). The second is a \emph{CVE feed}: a list of \mintinline{elixir}|%CVEEntry{}| records, each with a CVSS base score, drawn from the National Vulnerability Database~\cite{nvd} or, in the present evaluation, a synthetic generator with the same statistical shape.

\section{Attack-Graph Layer}
\label{ch:design:graph}

The attack-graph layer takes the data layer and produces a directed graph in the style of MulVAL~\cite{ou05mulval} and the multiple-prerequisite family~\cite{ingols06mpg}. Each node is a \emph{privilege assertion} (\enquote{attacker has user-level access on host $H$}); each edge is an \emph{exploit} annotated with the CVSS-derived probability of success. The graph is deliberately conservative: only edges supported by the data layer are added.

\section{Simulation Layer}
\label{ch:design:sim}

The simulation layer runs a fixed number of Monte Carlo iterations. In each iteration, a fresh attacker is dropped at the configured entry point, and propagation proceeds stochastically: at each step, the next exploit is drawn with probability proportional to its CVSS-derived weight. The output of one iteration is the set of nodes reached; the aggregate output is a \emph{blast-radius map} $\beta: V \to [0, 1]$, where $\beta(v)$ is the empirical probability that $v$ is reached across the run.

\section{Optimization Layer}
\label{ch:design:opt}

The optimization layer takes the blast-radius map and a budget $k$ of defensive actions, and returns a set of actions that minimizes the expected post-defense blast radius. Three families of actions are supported, in increasing order of expressive power:

\begin{itemize}
	\item \textbf{Min-cut segmentation.} Add edges (segmentation rules) that disconnect high-blast-radius subgraphs from the entry point. Solved by repeated application of a global min-cut on the weighted attack graph.
	\item \textbf{Greedy patching.} Sort vulnerabilities by their marginal reduction in blast radius, and patch the top $k$.
	\item \textbf{Hybrid.} Alternate one segmentation action and one patching action, comparing total blast-radius reduction at each step, until the budget is exhausted.
\end{itemize}

\section{UI Layer}
\label{ch:design:ui}

The UI layer is a Phoenix LiveView application. It shows the current blast-radius map as a heat map, allows the user to step through individual defensive actions and observe the resulting change in blast radius, and exports the final recommendation as a structured report.
